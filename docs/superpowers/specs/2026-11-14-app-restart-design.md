# 토핑 앱 다시 켜서 맞추기 — 설계 (짧은 버전)

## 목적
토핑 앱 화면과 스트림덱(플러그인) 값이 어긋나지 않게 한다.

## 원인 (Run.log, 2026-11-14 03:52 기록으로 확인)
- 앱은 꺼질 때 자기가 기억하던 값을 열린 작업공간 파일에 자동 저장한다 (`AutoSaveWorkspace: true`). 플러그인이 바꾼 값은 모른다.
- 앱은 꺼질 때 `sound_card_workspace_file.TPconfig`의 `LastWorkspaceOpened_E2x2_OTG`도 자기 기준으로 다시 쓴다.
- 앱은 켜질 때 그 작업공간 파일을 읽어 장치에 보낸다("同步的数据到设备").
- 그래서 플러그인이 저장/불러오기를 해도, 앱을 껐다 켜면 예전 값으로 돌아간다.

## 목표 / 하지 않을 것
- 목표: 저장·불러오기 뒤 앱이 그 작업공간으로 다시 켜져서 파일·장치·앱·스트림덱 값이 같아진다.
- 목표: 따로 누르는 '토핑 앱 다시 켜기' 키.
- 하지 않음: 앱 화면 자동 클릭, 앱 설정(`AutoSaveWorkspace`) 변경, 장치 드라이버 변경.
- 실패로 볼 것: 앱이 예전 값으로 자동 저장해 플러그인 값을 덮어쓰는 것, 48V가 뜻하지 않게 켜지는 것.

## 방법 (사용자가 고름: 1번)
1. **앱 강제 종료 후 다시 켜기 (선택)** — 강제 종료는 앱의 종료 시 자동 저장을 건너뛴다. 설정 파일의 마지막 작업공간을 바꾼 뒤 `--autostart`로 켜면 앱이 그 파일을 읽어 장치에 보낸다.
2. 앱 화면 자동 클릭 — 창이 방송 화면에 보이고 앱 업데이트에 약함. 버림.
3. 앱 자동 저장 끄기만 — 앱이 켜져 있는 동안 화면은 계속 어긋남. 버림.

## 동작
### 공통 '앱 다시 켜기' 순서 (`restartApp(name)`)
1. `ToppingPro.exe`만 강제 종료 (`taskkill /F /IM ToppingPro.exe`), 프로세스가 사라질 때까지 기다림 (최대 5초).
2. `TPconfig`에서 `LastWorkspaceOpened_E2x2_OTG`만 `name`으로 바꿔 씀 (다른 칸·형식 유지, 임시 파일 후 이름 바꾸기).
3. `ToppingPro.exe --autostart`를 앱 폴더에서 분리 실행 (알림 영역으로 켜짐).
- 앱이 원래 꺼져 있었어도 2, 3을 한다 (내 결정: 앱은 원래 늘 켜 두는 프로그램).

### 저장/불러오기 키
- 설정에 체크박스 **'토핑 앱 다시 켜서 맞추기'** 추가, 기본 켜짐, 키마다 해제 가능.
- 켜져 있으면: 저장(또는 불러오기)이 끝난 뒤 `restartApp(키 이름)`.
- 저장 키에서 이 옵션이 켜져 있으면 "앱이 쓰는 작업공간 이름" 거부를 풀어 준다 (강제 종료라 덮어쓰기 위험이 없음). 꺼져 있으면 지금처럼 거부.

### 새 액션 '토핑 앱 다시 켜기'
- 모드 선택, 기본 **가**.
  - **가. 맞추고 다시 켜기**: 지금 스트림덱 값을 앱이 열고 있는 작업공간 파일에 저장(기존 백업 규칙 그대로)한 뒤 `restartApp(그 이름)`. 작업공간을 아직 불러오지 않았으면 거부(경고 표시).
  - **나. 그냥 다시 켜기**: 저장 없이 `restartApp(앱이 열고 있는 이름)`. 앱 파일 값이 기준이 된다.
- 키 그림: 작업공간 키와 같은 모양, 위에 `RESTART`, 아래에 모드 이름.

## 제약
- 테스트는 가짜 프로세스 실행기와 임시 폴더로 한다. `C:\Program Files\TOPPING Pro`에 쓰는 테스트 금지.
- 실제 앱 종료 확인은 사용자 허락을 받고 한 번 한다: 강제 종료 시 자동 저장이 정말 안 되는지(Run.log에 종료 저장 줄이 없는지) 확인.
- 화면 글자는 한국어/일본어 번역(`ui/common.js` TEXT)에 추가, 매뉴얼 3개에 새 옵션과 키 설명 추가.

## 빌더에게 맡김
- 프로세스 대기 방식, 키 그림 세부 배치.
