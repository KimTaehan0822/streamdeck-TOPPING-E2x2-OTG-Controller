# TOPPING E2x2 OTG USB 분석 기록

## 장치 (2026-11-11 확인)
- VID `152A`, PID `8756`, 펌웨어 REV `0110`
- 드라이버: TOPPING Pro USB Audio Device Driver v5.74.0 (Thesycon TUSBAUDIO 기반)
- 토핑 앱: TOPPING Professional Control Center 1.13 (`ToppingPro.exe`, Qt5)
- HID 인터페이스 MI_04: `\\?\hid#vid_152a&pid_8756&rev_0110&mi_04#...`
  - 입력 리포트와 출력 리포트 모두 17바이트(리포트 ID 1바이트 + 데이터 16바이트), 피처 리포트 없음
  - 토핑 앱이 켜져 있어도 읽기 공유 모드로 열 수 있다. 장치가 보내는 입력 리포트는 연 쪽 모두에게 똑같이 온다.

## 앱이 쓰는 통로
- `hid.dll`: `HidD_SetFeature/GetFeature/GetInputReport`, 앱 안의 이름은 `tp_hid_new`, `tp_hid_new_recv`, `deal_tp_hid_new_recv_update`
- `ToppingProUsbAudioapi_x64.dll` (TUSBAUDIO API): `AudioControlRequestSet/Get`, `ClassVendorRequestIn/Out`, `Enable/Get/DisablePeakMeters`, `SetDspProperty`
- 어느 통로로 믹서 명령을 보내는지는 아직 모른다. USBPcap 기록이 필요하다.

## 장치 → PC 입력 리포트 (HID)
- 앱 화면이 떠 있을 때만 나온다. 앱이 미터를 요청하는 것으로 보인다. 처음 40초 기록에서는 전부 0이었다.
- 형식: `00 22 33 20 01 01 [코드 2바이트] FF FF FF [값 3바이트] 66 77 00`
- 약 68ms마다 12개 묶음이 온다. 코드는 `5A 02`, `5B 02`, `31 01`, `32 01`, `33 01`(두 번), `31 02`, `32 02`, `33 02`, `34 02`, `41 01`, `42 01`이다. 가끔 `21 01`도 온다.
- 음악에 따라 값이 바뀌므로 레벨미터로 추정한다. 코드와 채널의 대응, 값을 dB로 바꾸는 식은 아직 모른다.
- MUTE, 페이더를 조작해도 상태가 바뀌었다는 별도 리포트는 오지 않았다. 따라서 장치가 값을 먼저 알려 주지 않는다. 현재 값은 앱이 물어보는 방식으로 읽는 것으로 보인다.

## PC → 장치 출력 리포트 (USBPcap, 2026-11-11 확인)
- USB 주소 13(그때그때 바뀔 수 있음), 인터럽트 OUT 엔드포인트 `0x02`. 응답 리포트는 없다.
- 형식(리포트 ID 제외 16바이트): `22 33 20 01 01 [그룹] [항목] [값 4바이트, 빅엔디언] 00 00 66 77 00`
- 볼륨 값은 선형 배율이다. `값 = 10^(dB/20) × 0x02000000` (0dB = `02 00 00 00`, -1dB = `01 C8 51 F8`, -2dB = `01 96 B2 10`, -3dB = `01 6A 77 CC`). 0은 소리 없음이다.
- 관찰한 명령:
  | 앱 조작 | 보낸 리포트 | 해석(추정) |
  |---|---|---|
  | IN 1 MUTE 켜기 | `21 05` 값 `00000000` | MUTE = 게인을 0으로 보냄 |
  | IN 1 MUTE 끄기 | `21 05` 값 `02000000` | 0dB로 되돌림 |
  | IN 1 48V 켜기 / 끄기 | `21 02` 값 `00000001` / `00000000` | 켜기·끄기 |
  | Mix A PB 1/2 페이더 | 한 단계마다 4개: `61 05`=v, `62 05`=0, `61 06`=0, `62 06`=v | 61/62 = 믹스 출력 L/R, 05/06 = PB1/PB2 입력으로 추정(교차점 행렬) |
- 앱은 MUTE 같은 상태를 장치에 따로 저장하지 않고 게인 값으로 보낸다. 그래서 MUTE 해제 때 돌아갈 볼륨은 플러그인이 기억해야 한다.

## 플러그인 쪽 전송 시험 (2026-11-11, 성공)
- 토핑 앱이 켜진 채로 HID 장치를 쓰기 공유 모드로 열고 `WriteFile`로 17바이트(리포트 ID `00` + 16바이트)를 보냈다.
- `61 05`/`62 06`을 0으로 보냈다가 3초 뒤 `02000000`으로 되돌렸더니, Playback 1/2 음악이 헤드폰(OUT 1/2 = Mix A)에서 3초 동안 끊겼다가 돌아왔다(사용자 확인). 따라서 `61/62` = Mix A의 L/R, `05/06` = PB 1/PB 2가 맞다.
- 앱은 플러그인이 바꾼 값을 모른다. 앱 화면의 페이더는 예전 값을 그대로 보여 준다.
- 출력의 Mix 선택을 바꿀 때 앱이 `31 03`, `32 03` = `02000000`을 보냈다. 출력 소스도 같은 교차점 방식일 가능성이 있다(확인 필요).

## 믹스 행렬 (1차 기록, 2026-11-11)
- 그룹 = Mix 출력: Mix A `61`(L)/`62`(R), Mix B `63`/`64`, Mix C `65`/`66`, Mix D `67`/`68`
- 항목 = 입력: `01` IN 1, `02` IN 2, `03`/`04` IN OTG(Mobile IN) L/R, `05`/`06` PB 1/2, `07`/`08` PB 3/4, `09`/`0A` PB 5/6, `0B`/`0C` PB 7/8
- 스테레오 채널 한 칸 = 리포트 4개 (L→L = v, R→L = 0, L→R = 0, R→R = v).
- IN 1, IN 2는 모노: `6x 01`과 `6y 01`에 같은 값이 간다(가운데 Pan). IN 1+2 줄은 IN 1과 IN 2를 따로 움직였다.
- 앱에서 Mix를 바꿔 띄우면, 앱이 그 Mix의 교차점 24개를 한 번에 다시 보낸다(장치 값을 읽는 게 아니라 앱이 기억하는 값을 보냄).
- 0dB는 `01FFFFE0`나 `02000000`으로 온다. +1dB = `023E78D8`, +5dB = `038C5278`이다. 최대값은 아직 모른다.

## 출력·루프백 (2차 기록, 2026-11-11)
| 대상 | 볼륨 (항목 `03`, L/R) | 소스 선택 (항목 `01`) |
|---|---|---|
| OUT 1/2 | `31`/`32` | `35` |
| Mobile OUT | `33`/`34` | `36` |
| S/PDIF OUT(추정) | `5A`/`5B` | 미확인 |
| Loopback 1/2 | `51`/`52` | `57` |
- 소스 값: Mix A = `0B`, Mix B = `0C`로 보인다. Mobile OUT 기본값 `07`, Loopback 1/2 기본값 `08`. 작업 공간 파일의 `ChannelOUT_mode`(8/9/10)와 같은 번호다. 나머지 번호는 미확인.
- Mute와 Solo는 장치 기능이 아니다. 앱이 교차점 값을 바꿔서 흉내 낸다.
  - Mute: 그 채널의 교차점 4개를 0으로 보내고, 풀 때 원래 값을 다시 보낸다.
  - Solo: 같은 Mix의 다른 채널을 모두 0으로 보내고, 풀 때 Mix 전체를 다시 보낸다.
- **충돌 주의:** 앱은 Mix를 바꿔 띄울 때 자기가 기억하는 값으로 그 Mix 전체를 다시 보낸다. 그래서 플러그인이 바꾼 값을 앱이 덮어쓸 수 있다.

## 입력·소스 번호·Pan·LINK (3차 기록, 2026-11-11)
- 소스 번호(출력 `35`/`36`/`5C`, 루프백 `57` 공통, 사용자가 고른 순서와 맞춰 봄):
  | 번호 | 소스 | 번호 | 소스 |
  |---|---|---|---|
  | `0B` | Mix A | `03` | Input 2 |
  | `0C` | Mix B | `05` | Input 1+2 |
  | `0D` | Mix C | `02` | Mobile In |
  | `0E` | Mix D | `07` | Playback 1+2 |
  | `01` | Input 1 | `08` | Playback 3+4 |
  | | | `09` | Playback 5+6 |
  | | | `0A` | Playback 7+8 |
  `04`, `06`은 쓰이지 않았다. Mobile OUT 기본 `07`, Loopback 1/2 기본 `08`이다.
- S/PDIF OUT 소스 = `5C 01`.
- 입력 그룹: IN 1 = `21`, IN 2 = `23` (Mobile IN은 `22`로 추정, 미확인).
  - `2x 02` = 48V(1/0), `2x 03` = INST(1/0)
  - `2x 05` = 입력 배율. 디지털 게인, MUTE(0), Ø(음수, 0dB 반전 = `FE000000`)를 모두 이 값 하나로 보낸다.
- Pan(선형): 모노 IN 1을 왼쪽 끝으로 보내면 L = v, R = 0. 가운데는 L = R = v/2다. 스테레오 채널은 L과 R이 각각 따로 Pan된다(L 채널의 L/R 몫, R 채널의 L/R 몫).
- LINK도 앱이 흉내 낸다. LINK를 끄면 PB 1, PB 2가 각각 가운데 Pan의 모노가 된다(`61 05`=`62 05`=v/2). 다시 켜면 스테레오 값으로 돌아간다.
- 모니터 Gain = `35 02` (1/0).
- HP/TRS/AUX = `37 01`/`37 03`/`37 05` (1/0). 하나를 바꿔도 앱은 셋을 모두 보내고, 이어서 OUT 1/2 볼륨(`31 03`, `32 03`)도 다시 보낸다.
- 앱의 작업 공간 파일은 조작할 때마다 저장되지 않는다(마지막 저장 22:46, 조작은 그 뒤에도 계속함). 앱을 켜거나 끌 때 저장되는 것으로 보인다.

## 앱을 켤 때 (2026-11-11)
- 앱을 켜면 `11 01 = 1`(시작 명령으로 추정)을 보내고, 이어서 작업 공간에 저장된 값을 약 139가지 항목 모두 장치에 다시 보낸다.
- 장치가 보내는 입력 리포트 가운데 미터가 아닌 것은 `11 01`~`11 06`, `12 01`, `12 02`(장치 정보 응답으로 추정)와 `35 03`뿐이다. 믹서 값을 장치에서 읽어 오는 신호는 없다.
- **결론: 장치는 믹서 값을 기억해서 알려 주지 않는다. 믹서 값의 원본은 앱의 작업 공간 파일이다.** 앱을 끌 때 그 파일이 저장된다(23:10:32 저장 확인).
